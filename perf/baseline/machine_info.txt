Isolation notes (unchanged from the pre-Stage-5 PERFORMANCE.md): this is a
mobile-TDP laptop, not a tuned bare-metal box — no isolcpus, no disabled
Turbo Boost, no disabled SMT. Every benchmark that can pin its thread(s) does
(pin_current_thread_to + THREAD_PRIORITY_TIME_CRITICAL, restricted to
performance_core_ids()'s P-core set). Numbers will drift run to run on this
machine (background processes, thermal state, Turbo Boost) — this baseline
is one coherent, immediately-sequential run, not a multi-session average, and
is meant to be re-run rather than trusted as frozen truth. Compare
perf/baseline/2026-08-09_baseline_run.txt's numbers against the pre-existing
PERFORMANCE.md Stage 1-4 numbers for a sense of that run-to-run spread (e.g.
bench_sign's RSA-PSS p50 reads ~631us here vs. ~1.39ms in the earlier
document, and bench_pipeline_e2e's e2e p50 reads ~1.49us here vs. ~3.13us
there) — both are real, honestly-measured numbers from the same methodology
on the same physical machine; the spread itself is the evidence for why this
project reports full percentile distributions and re-runs rather than
memorizing a single number.

This file plus 2026-08-09_baseline_run.txt together are Stage 5's Section 1
deliverable: "a single baseline report" covering order submission,
